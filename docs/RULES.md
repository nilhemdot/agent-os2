# Rules

Status of every rule below: implemented and covered by unit tests + golden fixtures unless noted. "Misses" lists known gaps (see LIMITS.md).

| ID | Severity | Catches | Misses | False-positive notes |
|---|---|---|---|---|
| AG-001 | high (medium/low for some) | `permissions.allow` of `*`, bare/wildcard `Bash`, wildcard prefixes of curl/wget/rm/sudo/sh/python/node/ssh/docker/etc., writes outside the project, credential reads; `defaultMode` of `bypassPermissions`/`auto`/`dontAsk`; `skip*PermissionPrompt` in the shared file; low-severity hint when no deny rule covers secrets | Other broad-but-legitimate-looking allows (e.g. `Bash(npm run *)` that call attacker scripts), MCP tool wildcards | Teams that deliberately allow `Bash(python3 *)` get a high finding; suppress with a reason |
| AG-002 | info..critical | Hook `command`/`args` and helper keys (`statusLine`, `apiKeyHelper`, `awsAuthRefresh`, `awsCredentialExport`, `gcpAuthRefresh`, `otelHeadersHelper`, `fileSuggestion`, `subagentStatusLine`); `http` hooks to non-loopback URLs. Network tool, pipe-to-shell, base64-decode-run, inline interpreters, credential paths, repo scripts | Commands assembled at runtime, scripts that do the bad thing internally (repo script is medium only) | Benign formatter hooks are `info`; a hook that calls `curl` for a legitimate notification is high |
| AG-003 | critical/high | `enableAllProjectMcpServers: true`, `enabledMcpjsonServers` in the shared file | Approvals done in user-level files (out of scope) | Current Claude Code ignores committed approvals in untrusted folders; message says so |
| AG-004 | high / medium (low confidence) | `.claude/settings.local.json` in the git index | Other local files (e.g. `CLAUDE.local.md`) not yet covered | Unknown git state reports low confidence |
| AG-005 | critical..low | `env` overrides of `*_BASE_URL`/`*_API_BASE`/`*_ENDPOINT`/proxy variables to non-default hosts; `LD_PRELOAD`, `DYLD_*`, `BASH_ENV`, `NODE_OPTIONS` preloads, relative `PATH`, repo CA bundles, TLS verification off | Gateway hosts that look first-party | Corporate gateways look like attacks (medium confidence); loopback is low |
| AG-006 | high / info | MCP `command` that is a shell, shell-line string, or inline interpreter (`-c`, `-e`); shell operators in args | Obfuscated launchers behind a wrapper script | `cmd /c npx` idiom reported as info only |
| AG-007 | high / medium / low | npx/bunx/pnpm dlx/yarn dlx/npm exec/bun x/uvx/uv tool run/pipx run without an exact version; `-y`/`--yes` amplifier | Lockfile/integrity pinning (cannot be checked), docker image tags | Well-known packages (`@modelcontextprotocol/*`) are medium |
| AG-008 | high / medium | Token formats (GitHub, AWS, Slack, Stripe, OpenAI, Anthropic, Google, JWT, private keys, credentials in URLs, query-string secrets); key-name heuristic with entropy for confidence; literal Bearer values | Custom/unknown token formats with innocuous key names | Env references and doc sample keys are ignored; heuristic is medium at most |
| AG-009 | high / medium (low confidence) | `http://`/`ws://` to non-loopback; remote server with no visible auth | Auth handled by the client's OAuth flow (hence low confidence) | |
| AG-010 | high / medium (low confidence) | Filesystem server rooted at `/`, `~`, drive roots, home dirs, `..`; docker `-v` host root/home, docker socket, `--privileged`; exec-style server names (heuristic, unverified) | Servers that expose command execution under other names | Name heuristic is a guess |
| AG-013 | high/critical | MCP launch command references a repo script whose text contains credential-path reads, download-and-exec, base64-decode-and-run or pipe-to-shell (scripts are read as text, never run) | Scripts that fetch their behaviour at runtime, non-script entrypoints (compiled binaries), scripts > 256 KB or beyond 4 hops | Network-only or spawn-only local servers are intentionally not reported |
| AG-014 | high/medium/low | Package registry or index redirected away from the default hosts: `NPM_CONFIG_REGISTRY`, `PIP_INDEX_URL`, `UV_INDEX_URL`, `GOPROXY` etc. in agent settings `env` (high) and MCP `env` / `--registry` / `--index-url` args (medium); `registry=` in `.npmrc`, `npmRegistryServer` in `.yarnrc.yml`, `index-url` in `pip.conf`, `[[index]] url` in `uv.toml` (medium) | Indirect redirection (a script that rewrites config), `.pnpmrc`, Cargo/Maven/Gradle mirrors | Company mirrors look identical to attacks in a static file: medium confidence; loopback is low; default hosts (npmjs, pypi, GitHub Packages, ...) are not flagged |
| AG-020 | critical..medium | Zero-width, bidi, tag, variation-selector characters in any scanned file; decodes tag characters, zero-width binary (U+200B/U+200C), variation-selector bytes; ignores BOM at file start, valid emoji sequences, ZWNJ in Arabic/Indic scripts | Other steganography (homoglyphs, whitespace encodings), non-ASCII decoded payloads | Rare scripts that legitimately use joiners may be flagged at low confidence |
| AG-021 | critical/high/medium | Sentence with a secret reference near a send/upload verb, with a destination URL (critical for webhook/tunnel/`.invalid` host classes); no-URL variants are low confidence; negations ("never commit .env") are skipped | Paraphrase, non-English, instructions split across sentences | Documentation about secret handling can trip it; negation handling reduces this |
| AG-022 | high/medium | Ignore-previous, hide-from-user, covert action, false authority, bypass safeguards, act without confirmation | Subtle wording, other languages | "Without asking for confirmation" is common in autonomous workflows: medium, low confidence |
| AG-023 | high | Instructions to copy/spread agent config into other repos, issues, docs; hooks/tasks that write to CLAUDE.md, .mcp.json, rules, hooks | Propagation described indirectly | Ordinary "update CLAUDE.md" instructions are not flagged |
| AG-030 | critical/high/medium/info | `.vscode/tasks.json` tasks with `runOptions.runOn: "folderOpen"` (incl. windows/linux/osx overrides, args objects); watchers like `tsc -w` are info | Tasks that become dangerous via `dependsOn`, or settings that auto-allow tasks | `npm run` tasks are medium/low confidence |
| AG-011 | critical/high | MCP server launched (npx/bunx/pnpm dlx/uvx/...) from a package in `packages/core/src/intel/mcp-packages.json`: a **vulnerable** package is flagged only when the exact pinned version is in the affected range; a package **reported as malicious** is flagged for any version. Entries are verified (sources + access date) and offline. Today: `mcp-remote` 0.0.5 to <0.1.16 (CVE-2025-6514), `postmark-mcp` >=1.0.16 (backdoored release, since removed from npm) | Anything not on the short list; unpinned/ranged specs of vulnerable packages (the registry serves the fixed release); packages launched through scripts | Name matches are exact (look-alikes, scoped copies are not flagged). Entries with `verified: false` are ignored unless experimental rules are on |
| AG-012 | high/medium/low | **Lock-driven** (`verify` command only; needs a lock written by `lock`): an MCP server definition or hook command whose hash changed since it was locked (high, rug-pull class), appeared (medium) or disappeared (low). Evidence is a redacted `before: ... → after: ...` summaries | Anything not an MCP server or settings hook (tasks, helper commands such as `apiKeyHelper`, instruction files); drift inside referenced scripts | Intended changes are drift until `lock` is re-run. Re-ordered identical hooks are not drift |
| AG-024 | high/medium/low (**experimental**) | In instruction files: base64 (200+ chars; 80+ when it decodes to an instruction) and hex (128+; 80+ when it decodes to an instruction) blobs including MIME-wrapped ones; `data:` URIs (images low, text/application high); HTML comments of 40+ chars that read like instructions to an agent (and very long comments, low); link/image titles that read like instructions. Off unless `enableExperimentalRules` | Payloads in other encodings, split across files, or inside images; short payloads | Files that embed images or fixtures; long license comments (low). **Experimental because it fires on one existing fixture** (`heldout/04`, the HTML-comment payload AG-022 already reports) |
| AG-025 | high..critical | Skills, custom commands and subagents: `allowed-tools` that pre-approve every tool or any shell command (same classification as AG-001); subagent `permissionMode: bypassPermissions` and wildcard `tools`; risky commands in frontmatter `hooks`; risky commands in `!` + backtick-quoted blocks and fenced `!` blocks, which run when a skill is invoked. Pre-approvals tied to a project script (`Bash(python3 .claude/scripts/publish.py*)`, `Bash(node .claude/scripts/* *)`) are capped at medium; bare `Bash`, `Bash(*)` and open interpreter wildcards (`Bash(python3 *)`) stay high Frontmatter keys verified against the Claude Code skills and sub-agents docs | Agents that omit `tools` (they inherit everything by default, so absence is not flagged); inline `mcpServers` definitions; plugin-provided agents | A subagent in a session that already bypasses permissions inherits that mode regardless of its own setting |
| AG-000 | low | Config file could not be (fully) parsed | | |

**Script-following** (AG-002, AG-013, AG-030): files named by a hook, task or MCP command are read as text and scanned for network calls, credential paths, base64 decode-and-run and process spawning; findings are escalated by what the script contains and the evidence shows the chain (`a.sh → lib/b.js`, with file:line for each signal). Limits: 4 hops, 25 files, 256 KB each, repo-contained regular files only; indirect references built at runtime are not resolved.

All catalogued P0/P1 rules are now implemented. AG-012 runs only through `verify`; AG-024 is experimental (see its row). New rules must produce zero new findings on the existing fixtures or ship experimental (`docs/PARALLEL_RULES.md`); `packages/core/test/zero-new.test.ts` enforces it.
