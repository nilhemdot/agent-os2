# Limits

Tripwire is a read-only pre-flight check. It flags patterns; it does not make a repository safe.

- It cannot see malicious code in the project's own source files, dependencies, build scripts, or `package.json` scripts a hook or task may call.
- It cannot stop execution that happens before the scan runs, or by other tools. It does not block agents or extensions.
- Instruction-file rules (AG-021/022/023) are text heuristics. Paraphrase, other languages, or splitting an instruction across sentences can evade them. They also produce false positives on documentation that discusses these topics.
- Hook and task analysis is lexical: it normalizes quotes/backslashes and checks a fixed set of patterns. A command built from variables, a script the command downloads later, or an unlisted tool is not recognized.
- A file that the agent's parser reads differently from ours (parser differential) may hide content. Syntax errors are reported as AG-000 but cannot be fully reconciled.
- No runtime monitoring, no sandboxing.
- File formats and key names change. Only the Claude Code and MCP keys listed in docs/SOURCES.md were checked against current docs; Cursor, Codex, Gemini CLI, Windsurf and Cline coverage is discovery plus the shared MCP/instruction rules, and is unverified.
- `defaultMode` bypass in project files is high, not critical, because current docs say it is ignored there; older agent versions honored it.
- Git tracking status comes from `.git/index` or a caller-supplied list; repositories using unusual index extensions or sparse/worktree layouts may be reported as "unknown".
- Pinned versions are checked for form only (exact semver / `==`), not for whether that exact version is itself malicious. No network lookups are made.
- Not implemented yet: GitHub Action (Track B).
- **AG-011 intel is tiny and offline.** `mcp-packages.json` holds only entries checked against cited sources (currently `mcp-remote` CVE-2025-6514 and `postmark-mcp`). A package that is not listed is not known to be safe; the file is not updated automatically (no network). A vulnerable package is flagged only for an exact pinned affected version, so an unpinned or range spec of a vulnerable package is silent here (AG-007 reports it).
- **AG-012 lock covers MCP servers and settings hooks only.** It does not cover tasks, helper commands (`apiKeyHelper`, `statusLine`), instruction files, or the contents of scripts a hook runs. A lock proves "unchanged since locked", not "was safe when locked". The lock stores hashes and redacted summaries; the hash covers env and header values, so a change to a secret value is drift but is never printed.
- **AG-024 is experimental and heuristic.** Thresholds (200/128 characters, 40-character comments) are tuned to avoid noise; a short encoded payload, a different encoding, or text split across files is not found. Images are not decoded.
- **AG-025 relies on documented frontmatter keys.** Keys checked against the Claude Code docs on 2026-10-18 (`allowed-tools`, `permissionMode`, `tools`, `hooks`, shell-injection blocks); unknown keys are ignored as Claude Code ignores them. A subagent with no `tools` key inherits all tools and is not flagged.
- **Baselines are exact.** A baseline hides a finding while its rule, file, JSON path and evidence text are unchanged; any change to the evidence is a new finding by design. Stale baseline entries are reported, not removed.
- **Git hooks.** `hook install` refuses when `core.hooksPath` is visible in the repository config, its includes, the user config or the usual system config files, but git is never run, so a redirect set only through a mechanism it cannot see (for example a conditional include whose condition is not evaluated, or a system config in a non-standard place) is not detected. It never overwrites a hook it did not create.
- **Repository-provided configuration.** `diff` reads configuration and in-repository baselines from the base revision, so a change cannot excuse itself; `scan` reads the working tree (use `--no-repo-config` on untrusted trees). `verify` trusts the lock in the working tree unless `--lock-from <rev>` is given, so without it a change that edits a server definition and the lock together passes; in pull request checks use `verify --lock-from <base>`, which reads the lock from the base revision (the base branch must already contain a lock; the lock is still only as good as its review). The first pull request that introduces `.tripwire.json` gets no benefit from it, by design.
- **Credential-name exemptions in scripts (evasion risk).** When script-following reads a hook/task/MCP script, a credential filename is *not* counted as a read if it appears (a) in a list whose name or nearby text suggests it is protective (protect, guard, deny, ignore, exclude, allow, sensitive, ...), or (b) in an inline path guard such as `'.env' in file_path`, `p.endswith('.env.sample')` or `name === ".env"` on a line that does not itself call a read function. This removes false positives from guard scripts, but a malicious script could deliberately name a target list `allowed_paths` or hide a read behind a guard-looking line to avoid the credential-read signal. The exemption is withdrawn for the whole file when the file also makes a network call, so exfiltration still shows up as network + credential path; a local-only snooping script that dodges the heuristics would be missed. `.env.example`, `.env.sample`, `.env.template` and `.env.dist` are never counted as credentials.
- **Extension scope.** Only local `file:` workspaces are supported (not virtual/remote file systems). Tested only on the editors/versions in packages/extension/README.md. Explain Finding is rule-text only (no LLM). The extension reads files and shows diagnostics; it cannot stop an agent or another extension from running.
- **Diff / git reader.** See docs/DIFF.md: no SHA-256 repositories, reftable or partial-clone fetching; the base commit must be present locally (a shallow clone's oldest commit has no readable parent, reported as an error, not guessed); object ids are not re-hashed; merge-base for criss-cross history is a heuristic; renames are similarity-based (>= 80%).
- **Extension diagnostics are only as current as the last scan.** Edits to files other than agent-config files and the scripts they reference (found by file-name mention or previous scan evidence) do not trigger a rescan; use *Tripwire: Scan Workspace*.
- **Fixes edit text, not meaning.** A fix removes or rewrites the flagged text; it cannot know whether an entry was intentional, and it leaves referenced scripts in the repo untouched.

## History report

This report flags known risky patterns in the files that configure AI coding agents (agent settings, MCP server definitions, instruction files and tasks), using fixed rules, offline. It does not read your application source code, dependencies or build scripts, and it does not show that a repository is free of problems. Each finding is dated to the first-parent commit at which it appeared; commits that arrived through a merge are attributed to the merge, a renamed file starts a new finding, and a shallow or truncated history only gives 'on or before' dates. Monthly counts are computed by scanning the repository as it was at the end of each month with today's rules, so a rule added recently also counts findings from earlier months. Suppressions and size limits are read from the current version of the repository's configuration unless --no-repo-config is used.

- **Secret values in finding text.** Every finding's evidence, title, explanation and fix, and every output (text, JSON, SARIF, diff report, history report), is passed through the secret-pattern redaction (prefix and length only). Only the listed secret shapes are recognised; a credential in a format that is not in the pattern list can still appear in evidence that quotes a whole command.
